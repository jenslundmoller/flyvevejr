1. Where the script is installed

The site is static HTML on GitHub Pages. The files live in termik/output/ in the Flyvevejr repo.

PageTracked
/ (forecast map, index.html)Yes
/om.html (about page)Yes

The snippet is the one from the handover with one extra attribute:

<script defer src="https://mature-echidna.pikapod.net/stats.js"
        data-website-id="2246cd06-a205-4fdc-b6f7-4d612da2bb18"
        data-domains="flyvevejr.dk,www.flyvevejr.dk"
        data-exclude-hash="true"></script>

Why data-exclude-hash="true" is required: the map writes its state into the URL hash (#day=2&hour=15&lat=55.45&lon=11.65&zoom=9) with history.replaceState every time someone pans, zooms, or changes day or time. Umami counts every URL change as a new pageview. The first version went live without the attribute and logged a pageview for every zoom. It was added an hour later in commit a0e581c. Do not remove the attribute.

The downside is that the hash is not visible in Umami, so pageviews show as / and /om.html only. Day and time are still captured by the events below.

Content Security Policy: both pages have a CSP in a <meta http-equiv> tag. The Umami host was added to script-src and connect-src on both. om.html had no script-src before, so one was added ('self' + the Umami host).

Service worker: sw.js serves index.html cache-first, so the cache version was bumped (v18 to v19 for the script, v20 for the hash fix). Without that, returning visitors keep the old HTML. Remember to bump CACHE_VERSION whenever the snippet changes. The tracking requests are POST, which the service worker ignores.

2. Custom events

All events are on the forecast map (/) and were agreed with Jens. They only fire on a user's own actions. Settings restored from localStorage or the URL on page load are not counted.

EventPropertiesWhen
Dag valgtdag A day button is clicked. dag is the button text, e.g. I morgen or +3 dage.
Tidspunkt valgtkl The time slider is released, e.g. 15:00. Logged once on release, not on every step while dragging.
Favorit valgtflyveplads A favorite airfield is picked in the dropdown. (ingen) when cleared.
Favorit-dag klikketflyveplads, dag A day row in the favorite forecast is clicked (jumps to that day and airfield).
Kortlag skiftetlag The map layer is switched. Values: score, thermal-top.
Opdater klikketnone The "Opdater" button is clicked.
Sidepanel åbnet / Sidepanel lukketnone The sidebar is opened or closed, by click or by swiping the handle on mobile.
Om-siden åbnetnone The "Om denne side" link is clicked.

No double counting: a favorite day row triggers the day button with a programmatic click. The day button only logs Dag valgt for real clicks (event.isTrusted), so the row click is counted once, as Favorit-dag klikket.

Viewing properties in Umami: go to Events, open an event, and break it down by property, for example Favorit valgt by flyveplads or Dag valgt by dag.

Not tracked (by choice): clicks on airfield markers on the map, and map pan/zoom.

3. Implementation notes

  • Events are sent with a small helper, track(name, data), at the top of app.js, called from the existing handlers. It does nothing if the script is blocked, for example by an ad blocker, and swallows errors so analytics can never break the page.
  • The one exception is the "Om denne side" link, which uses the data-umami-event attribute. It is a normal same-tab link, so Umami's built-in navigation handling is fine there.
  • Thanks to data-domains, local development (localhost) sends nothing.
  • The forecast pipeline (GitHub Actions) only writes termik/output/data/*.json, so it never overwrites the HTML with the snippet.
  • Commits on main: bf96e98 (script, CSP, events), a0e581c (data-exclude-hash).
